# Data model (`src/db/schema.ts`)

SQLite (better-sqlite3), WAL, foreign_keys ON. Drizzle ORM; migrations in `drizzle/`, generated by `npm run db:generate`, auto-applied by `openDb()` (`src/db/index.ts`). Timestamps are unix seconds (`unixepoch()`).

## Enums

```ts
STATUSES   = ["triage","backlog","todo","in_progress","in_review","done","canceled"]
PRIORITIES = ["none","low","medium","high","urgent"]
actor.type = "human" | "agent"
issue.sourceType = "session" | "todo" | "ci" | "manual" | null
```

## Tables

| Table | Columns (⁕ = notable) |
|-------|----------------------|
| `actors` | id, name (unique), type, tokenHash⁕ (null for humans w/o API token), createdAt |
| `projects` | id, key (unique, e.g. `SYD`), name, nextIssueNumber⁕ (per-project counter), createdAt |
| `issues` | id, projectId, number (ref = `KEY-number`), title, description, status, priority, assigneeId, creatorId, parentId (sub-issues), labels⁕ (json string[]), sourceType/sourceDetail/sourceUrl⁕ (provenance), needsInput⁕ (bool), snoozedUntil, createdAt, updatedAt |
| `events` | id, issueId, actorId, type⁕ (free text: created, status_changed, commented, assigned, labels_changed, needs_input_cleared, …), payload (json), createdAt — append-only audit trail |
| `dependencies` | blockerId + blockedId (composite PK) — blocks/blocked-by edges |
| `sessions` | id, tokenHash (unique), actorId, expiresAt (30d), createdAt — human cookie sessions |
| `loginLinks` | id, tokenHash (unique), actorId, expiresAt (15 min), usedAt (single-use), createdAt |
| `attachments` | id, issueId, actorId, filename, contentType, size, createdAt — bytes on disk, not in db |
| `webhooks` | id, url, projectId (null = all projects), secret (HMAC), active, createdAt |
| `webhookCursor` | id, lastEventId — dispatcher's high-water mark |

## Conventions

- Issue ref format: `<PROJECT_KEY>-<number>` (`SYD-49`); parse via `parseRef` in `services/issues.ts`.
- `IssueView` = issue row + computed `ref` — the shape services/REST/MCP return.
- Issue state lives in mutable columns on `issues`; mutate only via services so the matching `events` row is co-written for the audit trail. `events` is not a fold/replay source — `description_changed`/`summary_changed` even carry empty payloads. Only attention, open-PR, and unanswered-questions are actually log-derived (queried from `events`, so they can't drift).
- Schema change flow: edit `schema.ts` → `npm run db:generate` → commit generated SQL in `drizzle/`.
